# ДЗ 3.7. Асинхронность и корутины

## Имитация установки

На экране приложения реализованы:

- запуск установки;
- обновление прогресса;
- отмена установки с возвратом в начальное состояние;
- отображение завершения установки.

Установка выполняется в корутине viewModelScope.
Для имитации ожидания используется delay.
Для отмены сохраняется Job запущенной корутины.

## Загрузка рейтингов

Количество приложений: 41.
Каждый запрос рейтинга имитирует задержку 1500 мс.

Фактические результаты:

- Последовательная загрузка: 61 599 мс.
- Параллельная загрузка: 1 510 мс.

Параллельный вариант оказался быстрее примерно в 40,8 раза.

## Объяснение результатов

При последовательной загрузке следующий запрос начинается только после завершения предыдущего. Время ожидания складывается: 41 × 1500 = 61 500 мс. Замер близок к этому значению.

При параллельной загрузке для каждого приложения запускается дочерняя корутина через async внутри coroutineScope. awaitAll ожидает завершения всех запросов.

Ожидания запросов перекрываются, поэтому общее время близко к задержке одного запроса — 1500 мс.

Небольшое превышение ожидаемого времени связано с выполнением кода и планированием возобновления корутин.

## Выводы

suspend сам по себе не запускает операции параллельно. В обычном цикле приостанавливающие вызовы выполняются по очереди.

async позволяет запустить несколько операций, результаты которых можно получить после совместного ожидания через awaitAll.

delay приостанавливает корутину, не блокируя поток. Поэтому интерфейс может оставаться отзывчивым даже при длительной последовательной загрузке.

Для перекрытия ожиданий не требуется отдельный поток на каждый запрос.

Результаты получены на имитации запросов. При работе с реальным сервером ускорение зависит от сети, ограничений клиента и сервера.
